# Спецификация model.json (v2)

## Обзор

Файл `src/model.json` описывает модель действий, объектов (с состояниями) и связей между ними.

Корневой объект содержит три массива:
- `model_actions` — действия
- `model_objects` — объекты с их состояниями
- `model_connections` — связи между действиями и состояниями объектов

---

## 1) model_actions

Массив действий. Каждое действие содержит:

| Поле            | Тип    | Описание                                          |
|-----------------|--------|---------------------------------------------------|
| `action_id`     | string | Уникальный идентификатор действия (`a00001`, …)   |
| `action_actor`  | string | Кто выполняет действие (может отсутствовать)       |
| `action_action` | string | Что именно делается                                |
| `action_place`  | string | Где выполняется действие (может отсутствовать)     |

**Ключ действия** (human-readable) формируется конкатенацией:
```
action_actor + " " + action_action + " " + action_place
```
Пустые/отсутствующие части опускаются при формировании ключа.

### Пример
```json
{
  "action_id": "a00001",
  "action_actor": "пользователь",
  "action_action": "создает документ",
  "action_place": null
}
```
Ключ: `"пользователь создает документ"`

---

## 2) model_objects

Массив объектов. Каждый объект содержит:

| Поле             | Тип    | Описание                                         |
|------------------|--------|--------------------------------------------------|
| `object_id`      | string | Уникальный идентификатор объекта (`o00002`, …)   |
| `object_name`    | string | Название объекта                                  |
| `resource_state`  | array  | Массив возможных состояний этого объекта          |

### resource_state

| Поле         | Тип    | Описание                                         |
|--------------|--------|--------------------------------------------------|
| `state_id`   | string | Уникальный идентификатор состояния (`s00002`, …) |
| `state_name` | string | Название состояния                                |

### Составной идентификатор состояния

Для использования в `model_connections` состояние идентифицируется **составным id**:
```
object_id + state_id
```
Например: объект `o00002` в состоянии `s00002` → `"o00002s00002"`

### Пример
```json
{
  "object_id": "o00002",
  "object_name": "документ",
  "resource_state": [
    {
      "state_id": "s00002",
      "state_name": "создан"
    }
  ]
}
```

---

## 3) model_connections

Массив связей. Каждая связь — направленное ребро графа:

| Поле             | Тип    | Описание                            |
|------------------|--------|-------------------------------------|
| `connection_out` | string | Откуда идёт связь (источник)        |
| `connection_in`  | string | Куда идёт связь (приёмник)          |

Связи бывают двух типов:

### Тип A: Действие → Состояние (final_states в старом формате)
Действие **порождает** состояние объекта.
- `connection_out` = `action_id` (например `"a00001"`)
- `connection_in` = составной id состояния (например `"o00002s00002"`)

### Тип B: Состояние → Действие (init_states в старом формате)
Состояние объекта **является предусловием** для действия.
- `connection_out` = составной id состояния (например `"o00002s00002"`)
- `connection_in` = `action_id` (например `"a00002"`)

### Пример
```json
[
  {
    "connection_out": "a00001",
    "connection_in": "o00002s00002"
  },
  {
    "connection_out": "o00002s00002",
    "connection_in": "a00002"
  }
]
```
Здесь: действие `a00001` создаёт состояние `o00002s00002`, которое является предусловием для действия `a00002`.

---

## 4) Соответствие со старым форматом (v1)

| Старый формат (v1)                        | Новый формат (v2)                                                  |
|-------------------------------------------|--------------------------------------------------------------------|
| Ключ действия (строка)                    | `action_actor` + `action_action` + `action_place`                  |
| `init_states` — массив строк              | `model_connections` типа B (состояние → действие)                  |
| `final_states` — массив строк             | `model_connections` типа A (действие → состояние)                  |
| Состояние — просто строка                 | Объект в `model_objects` с `resource_state`, составной id          |
| `b_value`                                 | Пока не перенесён в v2                                             |

---

## 5) Полный пример

```json
{
  "model_actions": [
    {
      "action_id": "a00001",
      "action_actor": "пользователь",
      "action_action": "создает документ",
      "action_place": null
    }
  ],
  "model_objects": [
    {
      "object_id": "o00002",
      "object_name": "документ",
      "resource_state": [
        {
          "state_id": "s00002",
          "state_name": "создан"
        }
      ]
    }
  ],
  "model_connections": [
    {
      "connection_out": "a00001",
      "connection_in": "o00002s00002"
    }
  ]
}
```
