# Структуры проверок и passage в TestGen

## Обзор
TestGen поддерживает:

1. **Структуры проверок** (`test_structure`):
   - `LEAF` — один кейс, одна проверка
   - `BRANCH` — все проверки последнего шага после последнего шага
   - `TREE` — проверки после каждого шага

2. **Режимы генерации путей** (`rounds`):
   - `ALL` — все пути
   - `QG` — путь с максимальным `b_value` на каждой развилке
   - `RANDOM` — взвешенно-случайный путь по `b_value`

3. **Режим прохождения шагов** (`passage`):
   - `API`
   - `UI`
   - `UI_FULL`
   - `MANUAL`
   - `MANUAL_FULL`
   - `NONE`

---

## 1) Структуры проверок (`test_structure`)

### LEAF
Один сценарий содержит одну финальную проверку целевого действия.

Формат:
```gherkin
Сценарий N Действие "Проверка"
Когда Шаг 1
Когда Шаг 2
...
Когда Действие
Тогда Проверка
```

### BRANCH
Один сценарий содержит все финальные проверки целевого действия после последнего шага.

Формат:
```gherkin
Сценарий N Действие
Когда Шаг 1
Когда Шаг 2
...
Когда Действие
Тогда Проверка 1
Тогда Проверка 2
```

### TREE
Проверки идут после каждого шага цепочки и в конце — проверки целевого действия.

Формат:
```gherkin
Сценарий N Действие
Когда Шаг 1
Тогда Проверка шага 1
Когда Шаг 2
Тогда Проверка шага 2
...
Когда Действие
Тогда Финальная проверка 1
Тогда Финальная проверка 2
```

---

## 2) Passage (`passage`)

Passage определяет, какой суффикс добавлять к строкам `Когда` и `Тогда`.

### NONE
Без суффиксов:
```gherkin
Когда Купить товар
Тогда Создан транш
```

### API
Все шаги и проверки помечаются `(API)`:
```gherkin
Когда Купить товар (API)
Тогда Создан транш (API)
```

### UI
Все шаги до последнего — `(API)`, последний шаг и его финальные проверки — `(UI)`:
```gherkin
Когда Оформить рассрочку (API)
Когда Купить товар (UI)
Тогда Создан транш (UI)
```

### UI_FULL
Все шаги и проверки помечаются `(UI)`.

### MANUAL
Все шаги до последнего — `(API)`, последний шаг и его финальные проверки — `(MANUAL)`.

### MANUAL_FULL
Все шаги и проверки помечаются `(MANUAL)`.

## 3) Пример (TREE + passage)

Базовый сценарий:
```gherkin
Сценарий 1 Купить товар
Когда Активировать кошелек
Тогда Кошелек активен
Когда Положить в корзину заказ на сумму X
Тогда Возможна рассрочка
Когда Оформить рассрочку
Тогда Оформлена рассрочка
Когда Купить товар
Тогда Создан транш
Тогда Сформирован график платежей
```

### TREE + API

Когда Активировать кошелек (API)
Тогда Кошелек активен (API)

## 4) Использование

В `run.py`:
```python
test_structure = "TREE"      # LEAF | BRANCH | TREE
rounds_type = "RANDOM"       # ALL | QG | RANDOM
passage = "UI"               # API | UI | UI_FULL | MANUAL | MANUAL_FULL | NONE
```

Вызов вывода:
```python
print_test_suites(
    cases,
    test_structure=test_structure,
    passage=passage,
)
```

---

## 5) Формулы количества сценариев

| test_structure | Формула |
|---|---|
| `LEAF` | `кол-во путей × кол-во final_states целевого действия` |
| `BRANCH` | `кол-во путей` |
| `TREE` | `кол-во путей` |

`passage` влияет только на пометки `(API/UI/MANUAL)`, но не меняет количество сценариев.
