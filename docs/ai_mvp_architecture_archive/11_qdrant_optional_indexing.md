# Module: Optional Qdrant Indexing

## Goal

Provide an optional semantic indexing layer for later search, triage, or dedup workflows without making the first MVP dependent on vector infrastructure.

## Recommended position

This module is **optional** in release 1. Implement the interface and data contract early, but keep runtime disabled by default.

## Recommended technologies

- Qdrant
- one collection for chunks or actions, or separate collections if clearly justified
- payload indexes on commonly filtered fields

## What to index

Prefer indexing one of these, not everything at once:

### Option A: normalized actions
Best when future search is around operational semantics.

### Option B: selected high-value chunks
Best when future retrieval for inspection is important.

For MVP, action indexing is usually more meaningful than paragraph indexing.

## Collection design

Suggested payload fields:
- `document_id`
- `run_id`
- `chunk_id`
- `entity_type`
- `action_canonical`
- `primary_object_key`
- `section_path`
- `status`

Create payload indexes for fields used in filters.

## Upsert policy

Point ids must be deterministic:
- action id,
- or chunk id.

Do not create new points for every rerun unless versioning semantics explicitly require it.

## Embedding policy

Keep embedding generation outside this module's core responsibilities if possible.
This module should accept vectors + payload and handle indexing.

## Failure policy

Indexing failure should not fail the whole MVP run unless semantic search is a hard requirement.

Preferred behavior:
- mark run `partial_success`,
- record indexing failure event,
- allow core extraction result to remain available.

## Acceptance criteria

- indexing can be turned on/off by config,
- deterministic point ids prevent duplication,
- filtered search fields are planned up front,
- indexing errors are visible but non-catastrophic by default.

## Common pitfalls

- making vector indexing a hard dependency before it is needed,
- indexing every low-value text fragment,
- missing payload indexes for frequent filters,
- using unstable autogenerated point ids.
